# wujian100_open 总线接口分析

> 面向"要改 RTL / 要写驱动 / 要调时序"的人：把总线拓扑、信号级接口、地址译码、仲裁策略、访问时序、异常响应全部落到具体文件和行号。
> 行号基于当前仓库版本，行号漂移时按关键词检索。

---

## 0. 结论速览

| 维度 | 结论 |
|---|---|
| 总线体系 | 两级 AHB-Lite 交叉开关 + 两条 APB 总线，**不含 AXI，不引出片外** |
| 主总线 | `ahb_matrix_7_12_main`，7 主 × 12 从，`soc/matrix.v:34729` |
| 低速总线 | `ahb_matrix_1_6_sub`，1 主 × 6 从，`soc/matrix.v:1386`，带可选分频/异步 FIFO |
| 外设总线 | APB0（`0x5000_0000`）、APB1（`0x6000_0000`），各 16 个叶子槽，`soc/params/apb{0,1}_params.v` |
| 真正在跑的 CPU 主口 | 只有 **M0（取指）** 和 **M2（数据/外设）**，M1 被常量 0 绑死 |
| 仲裁策略 | **固定优先级**，M6 > M5 > M4 > M3(DMAC) > M2 > M1 > M0(CPU 取指) |
| 数据位宽 | 全部 32 bit，支持 byte/half/word，**APB 侧只认对齐访问** |
| 异常响应 | 主矩阵未命中 → 2 拍 `HRESP=ERROR`；低速矩阵未命中 → 静默 `OKAY`（数据 0）；APB 内未命中 → `PSLVERR → HRESP=ERROR` |
| 时钟 | 开放版全部同源同频（`soc/clkgen.v:395-425`），跨域 FIFO 存在但被 bypass |

## 1. 层级拓扑

```
E902 CPU (soc/E902_20191018.v)
├── IAHBL 口  ──→ M0 ┐
├── DAHBL 口  ──→ M1 ┤  (M1 恒 0，见 §3)
└── SAHBL(BIU)口 ─→ M2 ┤
                        ├── ahb_matrix_7_12_main  (hclk = soc_hclk)
 DMAC  ────────────→ M3 ┤   │
 dummy ────────────→ M4~M6┘  │
                             ├─ S0  ISRAM  64KB
                             ├─ S1  imem dummy (预留片外指令存储)
                             ├─ S2~S4  DSRAM 3×64KB
                             ├─ S5  dmem dummy (预留片外数据存储)
                             ├─ S6  DMAC 寄存器
                             ├─ S7~S9 dummy
                             ├─ S10 ──→ ahb_matrix_1_6_sub  (低速总线桥)
                             │           ├─ S0/S1 dummy
                             │           ├─ S2 → APB0 ──→ 16 个 psel
                             │           ├─ S3 → APB1 ──→ 16 个 psel（含 AOU 域 GPIO/RTC/PMU）
                             │           └─ S4/S5 dummy
                             └─ S11 dummy
```

对应 RTL 实例层级：
`soc/pdu_top.v:949` 例化 `ahb_matrix_top`（总线域集成）→ 其内部 `soc/ahb_matrix_top.v:567` 才是 `ahb_matrix_7_12_main`；
低速总线 `soc/pdu_top.v:1061` → `soc/ls_sub_top.v:204` 的 `ahb_matrix_1_6_sub`；
APB0 见 `soc/pdu_top.v:1112`，APB1 见 `soc/pdu_top.v:1242`。
矩阵模块本体都在 `soc/matrix.v`：`ahb_matrix_7_12_main`(:34729)、`ahb_matrix_7_12_dec`(:31794)、`ahb_matrix_7_12_arb`(:1859)、`ahb_matrix_1_6_sub`(:1386)。

## 2. 信号级接口

### 2.1 主口（AHB Master）

每个主口只有 8 根请求 + 3 根响应：

| 方向 | 信号 | 位宽 | 说明 |
|---|---|---|---|
| → | `HADDR` | 32 | 字节地址 |
| → | `HTRANS` | 2 | `00` IDLE / `10` NONSEQ / `11` SEQ；**矩阵只判 `[1]`** |
| → | `HWRITE` | 1 | 1 写 0 读 |
| → | `HSIZE` | 3 | `000`B / `001`H / `010`W |
| → | `HBURST` | 3 | 直通到从口 |
| → | `HPROT` | 4 | 直通到从口；APB 侧重编码为 `PPROT` |
| → | `HWDATA` | 32 | 写数据 |
| ← | `HRDATA` | 32 | 读数据 |
| ← | `HREADY` | 1 | 传输完成 / 插入等待 |
| ← | `HGRANT` | 1 | 授权指示（仅信息，**主设备不必等待**） |

### 2.2 从口（AHB Slave）

比主口多一根 `HSELX`（低有效语义的选中指示，实际用法为高有效选中），其余同上加 `HRESP[1:0]`。

### 2.3 该实现**不支持**的 AHB 特性

| 特性 | 状态 | 证据 |
|---|---|---|
| `HBUSREQ/HLOCK`（总线请求/锁定） | 矩阵端口里根本没有 | `grep -c hbusreq soc/matrix.v` = 0 |
| `HMASTER/HSPLIT/RETRY 组合` | 无 HMASTER，无 SPLIT | 同上 |
| `HRESP` 双周期响应语义 | **简化**：ERROR 通过 `addr_err_d/addr_err_d2` 打两拍 | `soc/matrix.v:33729-33745` |
| `HRESP=RETRY` | SRAM 控制器保留但默认不产生（`sms_resp` 恒 OKAY） | `soc/sms.v:457` |
| 独占访问（Exclusive） | 无 `HEXCL/HEXOKAY` | — |

> 结论：这是一套 **AHB-Lite 的裁剪实现**，直接搬 ARM AHB 规范里的 burst 语义到别的 IP 上会踩坑。

## 3. 主设备：三个 CPU 口只有一个半在用

`core_top.v:505-533` 把 E902 的三个口直接映射到 M0/M1/M2：

| 主口 | 来源 | 实际用途 |
|---|---|---|
| M0 | `iahbl_pad_*` | 指令口（IAHBL） |
| M1 | `dahbl_pad_*`，**被常量 0 绑死**（`core_top.v:583-589`） | 恒空闲 |
| M2 | `biu_pad_*`（SAHBL） | 所有数据访问 + 外设访问 |
| M3 | DMAC `m_*` | DMA 搬运 |
| M4/M5/M6 | `ahbm_dummy_top` | 从不发请求，纯占位 |

### 3.1 地址如何被分到 M0 / M2

E902 内部先用 BMU 做一次分流（`E902_20191018.v:935`）：

```verilog
assign iahbl_hit = ((lsu_bmu_addr[31:20] & pad_bmu_iahbl_mask[11:0]) == pad_bmu_iahbl_base[11:0]);
```

而 `core_top.v:476-477` 把窗口写死为 `base = 12'h000`、`mask = 12'hE00`。
`12'hE00` 只保留 `addr[31:29]`，所以：

- `addr[31:29] == 000` → `0x0000_0000 ~ 0x1FFF_FFFF` → **走 M0**
- 其他所有地址（含 DSRAM `0x2000_0000`、全部外设） → **走 M2**

同时 `E902_20191018.v:932` 把 `dahbl_hit` 直接接 `1'b0`，DAHBL 通路在核内就是关闭的。

### 3.2 一个能自证的推论

因为 **ISRAM 在 `0x0000_0000`（走 M0）、DSRAM 在 `0x2000_0000`（走 M2）**，
所以 `tb/busmnt.v:63-67` 只挂 M2 就能抓到 `0x2000_7C50` 的 PASS/FAIL 写操作。
这也是为什么 `printf` 落地的每一个字符都能被 `busmnt` 打印出来（`tb/busmnt.v:121`）。

> 反过来说：**如果哪天把 DSRAM 搬到 `0x1xxx_xxxx`，`busmnt` 会立刻全部失聪**，因为流量改走 M0 了。改地址映射时必须同步检查这里。

### 4.5 每个 tim 块是双定时器

`tim0_sec_top` 内 `paddr[TIMER_ADDR_LHS:2]` 译码，偏移 `0x00`/`0x04`/`0x08`/`0x0C` 属第一路，`0x14`/`0x18`/`0x1C` 属第二路（`soc/tim.v:175-240`）。
8 个块 × 2 = 16 个定时器，与 `soc.h:101-116` 的 16 个 `WJ_TIMERx_BASE` 对得上。

### 4.6 dummy 从设备的坑

`ahb_dummy_top`（`soc/dummy.v:68-70`）恒输出：

```verilog
assign hrdata = 32'b0;
assign hready = 1'b1;
assign hresp  = 2'b00;   // OKAY
```

也就是说 `0x1000_0000`、`0x3000_0000`、`0x4001_0000`、`0x8000_0000` 这些区域**读回 0、写被丢弃、但不报错**。
软件在这些地址上"跑通了"不代表外设存在——这是最容易被误判为"功能正常"的地方。

## 5. 仲裁：固定优先级，没有 round-robin

`ahb_matrix_7_12_arb` 里每个从口一个优先级编码器（`soc/matrix.v:3508-3519`）：

```verilog
assign s0_req_all[6:0] = s0_req[6:0] | s0_req_pend[6:0];
casex (s0_req_all[6:0])
  7'b1??????: s0_gnt = 7'b1000000;   // m6 最高
  7'b01?????: s0_gnt = 7'b0100000;
  ...
  7'b0000001: s0_gnt = 7'b0000001;   // m0 最低
endcase
```

**优先级从高到低：M6 > M5 > M4 > M3 > M2 > M1 > M0**

M4~M6 是 dummy，不会请求，所以实际生效的优先级是：

```
DMAC(M3)  >  CPU 数据/外设口(M2)  >  CPU 指令口(M0)
```

### 5.1 这意味着什么

1. **DMA 优先级高于 CPU**。DMA 做连续搬运时，CPU 的取指和数据访问都要排队。
2. **CPU 取指口 M0 是全场最低优先级**。而 ISRAM（`0x0`）代码执行的取指正好走 M0。
   → 极端场景：DMA 长时间占用 S0/S2，CPU 从 ISRAM 取指会被持续饿住，表现为"程序莫名变慢/超时"。
3. `s*_req_pend` 保证未被及时服务的请求不会丢（有 hold 语义），但不改变优先级顺序。
4. **没有 `HBUSREQ/HLOCK` 通路**：`ahb_matrix_top.v:956-958` 把 DMAC 的 `m_hbusreq/m_hlock` 接出来后**悬空**，矩阵不认。DMA 不能"锁总线"，也不能保证多拍原子性。

## 6. 主矩阵微架构

由两个子模块组成：`ahb_matrix_7_12_dec`（`matrix.v:31794`，按主口拆命令）+ `ahb_matrix_7_12_arb`（`matrix.v:1859`，按从口仲裁）。

### 6.1 命令走 45 bit 控制总线

```verilog
// matrix.v:34321
assign {s0_haddr[31:0], s0_htrans[1:0], s0_hsize[2:0],
        s0_hburst[2:0], s0_hprot[3:0], s0_hwrite} = s0_ctrl_bus[44:0];
```

地址/属性与写数据是**分开两条路径**：控制走 `s*_ctrl_bus`，数据走 `s*_hwdata`（`matrix.v:34333`）。
好处是地址相位可以提前于数据相位送到从口，读延迟被流水掩盖。

### 6.2 命令/数据相位寄存器

`dec` 内部有 `m*_latch_cmd`、`m*_cmd_cur/last`、`m*_data` 等握手信号，保证：
- 地址相位送出后，若从口 `HREADY=0`，地址与属性保持有效（AHB 规范要求）；
- `SEQ` 传输的地址由主设备自己递增，矩阵不做地址计算（真正的 AHB 行为）。

### 6.3 burst 是否被打断

主矩阵**原样透传** `HTRANS`/`HBURST`，不拆突发。
但下游从口不一定吃 burst：

- **S0（ISRAM）连 `HBURST` 都没有引出**（`ahb_matrix_top.v:191-197` 只有 `haddr/hprot/hsel/hsize/htrans/hwdata/hwrite`）；SRAM 控制器只看 `HTRANS` 判 `NONSEQ/SEQ`（`sms.v:92-94`），靠地址自增实现连续访问。
- **S10（低速总线）把所有传输强制改成 `NONSEQ`**（见 §7）。

## 7. 低速总线：一个被 bypass 的跨时钟桥

`soc/ls_sub_top.v` 把主矩阵 S10 接到 `ahb_matrix_1_6_sub`，但这个 1×6 矩阵里塞了两级异步 FIFO（`matrix.v:1770`、`:1805`）：

```
主域 hclk ──[AFIFO 77bit: haddr+htrans+hsize+hburst+hprot+hwrite+hwdata]──→ 低速域
主域 hclk ←─[AFIFO 35bit: hrdata+hresp+vld  ]── 低速域
```

### 7.1 关键：本集成把分频关掉了

```verilog
// soc/ls_sub_top.v:218
.pmu_matrix_clkdiv_bypass (1'b1),
```

bypass=1 时（`matrix.v:1848-1856`）地址/数据**直接透传，FIFO 完全不参与**，低速总线与主总线同频同相。
也就是说这套"半速总线 / 异步桥"的硬件能力是存在的，但**当前 SoC 没用**。想降功耗或降频跑外设，把这个参数改成 0 即可（改之前要确认 CDC 端的复位 `clk_div_rst` 行为）。

### 7.2 传输被拆成单拍

```verilog
// matrix.v:1307-1318
assign s0_htrans[1:0] = (s0_cur_cmd | s0_last_cmd) ? 2'b10 : 2'b00;  // 全部 NONSEQ
```

无论主设备发的是 `SEQ` 还是 `INCR16`，到 APB 侧一律变成一个个独立 `NONSEQ` 单拍。
**这就是"经 APB 访问不能用 burst 提速"的根因**：不是 APB 不支持，是这一层主动拆掉了。

### 7.3 一个静默黑洞

1×6 矩阵**没有地址错误检测**：`m_hresp` 只是从口 `hresp` 的 mux（`matrix.v:1347-1353`），
而 `S_IDLE` 状态下 `m_hready = 1'b1`（`matrix.v:1363`）。

后果：命中主矩阵 S10 但没命中任何低速从口的地址（例如 `0x4020_5000`、`0x4040_0000`、`0x5005_0000`）
→ **1 拍返回 OKAY，读回 0，不报错**。

对比 §9，三种"没命中"的行为完全不一样，很容易踩。

## 8. APB 桥：时序与限制

### 8.1 结构

`csky_apb0_top` / `csky_apb1_top` 内含：
- `apb0_state_ctrl`：AHB → APB 协议转换状态机（`apb0.v:83`）
- `apb0_leaf_mux`：16 路 `PSEL` 译码 + `PRDATA` 选择（`apb0.v:11`）

### 8.2 状态机

```
IDLE ──写──→ WTW ──→ SPW ──→ ASW ──(PREADY)──→ IDLE
IDLE ──读──→ SPR ──→ ASR ──(PREADY)──→ IDLE     (pclk_en=0 时先插 WTR)
```

`HREADY` 的生成（`apb0.v:130-139`）：

```verilog
assign ahb_req = i_slave_hsel & i_slave_htrans[1] & i_slave_hreadyin;
always @(posedge i_hclk ...)
  if (o_slave_hreadyout == 1'b1)      o_slave_hreadyout <= ~ahb_req;          // 拉住一拍
  else if (o_root_penable && i_pclk_en) o_slave_hreadyout <= i_root_pready;
```

### 8.3 时序（按 FSM 推导，未实测）

| 访问 | 从地址相位到 HREADY 拉高 | 说明 |
|---|---|---|
| APB 读 | **≈3 个 hclk** | IDLE→SPR→ASR |
| APB 写 | **≈4 个 hclk** | IDLE→WTW→SPW→ASW |

所有 16 个叶子的 `PREADY` 在 `apb0_sub_top.v:563-578` / `apb1_sub_top.v` 里被**硬接 `1'b1`**，
所以每个叶子都是 0 等待，上表是确定值而不是典型值。

### 8.4 字节使能：只支持对齐访问

`PPROT/PSTRB` 由 `HADDR[1:0]` + `HSIZE` 组合生成（`apb0.v:205-239`）：

| HADDR[1:0] | HSIZE | PSTRB |
|---|---|---|
| `00` | byte/half/word | `0001` / `0011` / `1111` |
| `01` | byte | `0010`，其他 **`0000`** |
| `10` | byte / half | `0100` / `1100`，word **`0000`** |
| `11` | byte | `1000`，其他 **`0000`** |

**非对齐访问（如 `*(u32*)0x50000002 = x`）不会报错，但 `PSTRB=0`，写操作被静默丢弃。**
读不受影响（`PRDATA` 照常返回整个字）。写外设寄存器时务必保证对齐。

`PPROT = {~HPROT[0], ~HSEC, HPROT[1]}`，数据访问恒为 `3'b010/011` 一类，安全属性不做区分。

### 8.5 错误传播

```
叶子 PSLVERR=1 ──→ pslverr（寄存一拍）──→ HRESP=ERROR
无叶子命中（psel 有效但 leaf_psel 全 0）──→ root_pready_abnormal=1, root_pslverr=1 ──→ HRESP=ERROR
```

`apb0.v:61-65` 的 `root_pready_abnormal` 是 APB 侧比低速矩阵严谨的地方：**APB 有黑洞检测**。

## 9. 三种"访问不到"的行为对照

| 层级 | 场景 | HREADY | HRESP | 数据 |
|---|---|---|---|---|
| 主矩阵 | 地址不在 12 个窗口内（如 `0x2003_0000`） | 正常 | **ERROR**（2 拍） | 0 |
| 主矩阵 → dummy 从口 | 命中 dummy（如 `0x1000_0000`） | 正常 | OKAY | 0（写丢弃） |
| 低速矩阵 | S10 内但无 6 口命中（如 `0x4020_5000`） | 正常 | **OKAY（静默）** | 0 |
| APB 桥 | `psel` 有效但无叶子（如 `0x5003_5000`） | 正常 | **ERROR** | 0 |

调试建议：怀疑地址错时，先看是 `HRESP=ERROR` 还是"OKAY 但读到 0"。后者才是最难查的。

## 10. 访问时序速查

| 目标 | 周期（hclk） | 备注 |
|---|---|---|
| ISRAM / DSRAM 读 | 1 | 0 等待（`sms.v:460` `hready_s=1'b1`） |
| ISRAM / DSRAM 写 | 1 | |
| 写后立刻读**同一 bank** | +1 | 单口 RAM 冲突，`read_after_write_access` 拉低 `HREADY`（`sms.v:458`） |

## 11. 验证接口：`tb/busmnt.v`

`busmnt` 不是通用 AHB VIP，而是**挂死在一个魔数协议上的探针**，只嗅探 CPU M2：

- 触发条件：`HTRANS==2'b10 && HREADY && HWRITE`（`busmnt.v:152`）——只抓 `NONSEQ` 写，`SEQ` 一律漏；
- `0x2000_7C50` ← `0x1001`：第一次记 `fail_mark`，第二次 `$finish` 并写 `TEST FAIL`；
- `0x2000_7C50` ← `0x2002`：第一次记 `pass_mark`，第二次 `$finish` 并写 `TEST PASS`；
- `0x2000_7C50` ← 其他值：当作字符输出（`$write("%c")`，实现 printf）；
- `0x2000_7C60`–`0x2000_7C9C`：16 个 GPR 快照，落 `rtl_gpr.log`。

**注意两点**：
1. 需要**连续两次**写 `0x2000_7C50` 才会结束，因为第一次只是"武装"标志位（`pass_mark_times`）。
2. 只认 M2。任何把数据流量改到 M0/M1 的地址映射调整都会让监控彻底失效。

## 12. 设计风险与改动建议

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 固定优先级，DMAC(M3) > CPU(M2/M0)，且 M0 最低 | DMA 大流量时 CPU 取指被饿 | 给主矩阵加 round-robin，或至少把 M0 提到 M3 之上；短突发 + 通道间加权 |
| 2 | 低速矩阵无地址错误检测 | 未映射地址静默成功 | 照抄主矩阵 `addr_err` 逻辑加进去（几十行） |
| 3 | dummy 从口返回 OKAY | 掩盖误访问，软件难查 | 改成返回 ERROR，或加一个只读 ID 寄存器 |
| 4 | APB 非对齐写静默丢弃（PSTRB=0） | 驱动写寄存器偶发失效 | 加 `HSIZE/HADDR` 合法性检查 → 返回 `PSLVERR` |
| 5 | `HBUSREQ/HLOCK` 悬空（`ahb_matrix_top.v:956-958`） | DMA 无法锁总线，多拍原子性无保障 | 明确文档化；若需要，接进仲裁器 |
| 6 | 主矩阵地址译码是 12×7 段裸比较，硬编码 | 加外设要改 `matrix.v` 36667 行大文件 | 参照 APB 的做法抽成 `params` include |
| 7 | S0（ISRAM）无 `HBURST` 端口 | 无法做 burst 优化/预取 | 若换 SRAM 控制器，顺手补上 |
| 8 | 低速总线跨域 FIFO 被 bypass | 潜力浪费 | 想跑半速外设时把 `pmu_matrix_clkdiv_bypass` 改成 0，并做 CDC 验证 |
| 9 | 时钟树全同源（`clkgen.v:395-425`） | 开放版看不到真实低功耗门控 | 上 FPGA/流片时必须替换 `clkgen`，PMU 端口语义按 `pmu_*_clk/rst_b` 保留 |
